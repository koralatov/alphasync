# Technical guide

Version **2.0.2** is the current release of the Swift rewrite, developed on **master**. It includes the unpublished 2.0.1 maintenance work. Both app targets require **macOS 13 or later**. For installation and everyday use, see the [README](README.md).

## Shared source and editions

| Target and scheme | Architectures | Minimum macOS | Icon |
| --- | --- | --- | --- |
| AlphaSyncUniversal | x86_64 and arm64 | 13.0 | Original |
| AlphaSyncAppleSilicon | arm64 | 13.0 | Modern |

Each target embeds its matching Swift `AlphaSyncLauncher.app` in `Contents/Library/LoginItems`. Apps and helpers use the existing bundle identifiers, `com.tsoniq.AlphaSync` and `com.tsoniq.AlphaSyncLauncher`, and share version and build settings. Install one app edition at a time.

The application, business logic, protocol engine, and codecs are Swift. The file manager uses SwiftUI’s sidebar, table, toolbar, forms, sheets, and window scenes. A small public AppKit adapter provides genuinely non-editable selectable text and the native Find bar on macOS 13. Pasteboard, Help Viewer, workspace actions, and orderly termination also use public native integrations. There are no third-party runtime dependencies.

The shared Swift package contains:

- `AlphaSyncCore`: bounded binary parsing, typed snapshots, protocol transactions, codecs, limits, and atomic local files.
- `AlphaSyncHardware`: serial USB ownership, discovery, async operations, backups, and recovery copies.
- `AlphaSyncUI`: shared SwiftUI views, preferences, and commands.

`Sources/AlphaSyncApp` and `Sources/AlphaSyncLauncher` provide the executable entry points. Only the dedicated arm64 target compiles `Sources/AlphaSyncSilicon/EditionGuard.swift`. This rejects an Intel or incorrectly configured Silicon build and provides a place for future genuine architecture-specific integrations. No exclusive hardware feature has been invented for the current edition. Swift concurrency is shared by both architectures.

The [migration plan](docs/1.6-migration.md) records decisions, milestones, and outstanding validation.

## Build

Use **Xcode 26.6**, pinned in [.xcode-version](.xcode-version), for canonical development packages. CI also checks the Universal target on an Intel host with Xcode 16.4. Both use Swift 6 with strict concurrency checking. The build host can run a newer macOS than the app’s minimum.

```sh
xcodebuild -project AlphaSync/AlphaSync.xcodeproj \
  -scheme AlphaSyncUniversal -configuration Release \
  -destination 'generic/platform=macOS' \
  -derivedDataPath build/DerivedData build

xcodebuild -project AlphaSync/AlphaSync.xcodeproj \
  -scheme AlphaSyncAppleSilicon -configuration Release \
  -destination 'generic/platform=macOS' \
  -derivedDataPath build/DerivedData build
```

Apps and separate dSYMs appear under `build/DerivedData/Build/Products/Release/universal` and `Release/apple-silicon`. Keep each app bundle intact. [Version.xcconfig](AlphaSync/Build/Version.xcconfig) supplies version **2.0.2**, build **151**, and the **stable** release channel to both apps and helpers.

The checked-in Xcode project is generated by `python3 scripts/generate-project.py`. Run it after changing target definitions in that script. Generation uses Python’s standard library and preserves stable object identifiers. Python is not required to run the app.

## Milestone checks

Routine commits use `[skip ci]`. Compile and test at the documented major milestones, completion, or a focused correction to a failed milestone.

```sh
swift build --product AlphaSyncUIChecks
swift test --parallel
swift run --skip-build AlphaSyncUIChecks build/interface-checks
```

Core regressions cover wire frames, truncated replies, character conversion, UTF-16 byte orders, dictionary bounds, unsupported text, file limits, low memory, exclusive exports, and incomplete folders. Simulated transfer checks include multi-block writes, read-back mismatches, changed originals, and a 2 MB import rejected before file-writing commands.

The [manual regression workflow](.github/workflows/regression-checks.yml) checks an exact source commit on Intel and Apple Silicon without building app bundles or downloads.  It compiles the shared libraries and interface-check executable, runs core and simulated device-service tests, validates disposable package fixtures, and retains logs and interface captures.  Canonical CI reads `.xcode-version`; the Intel compatibility compiler remains an explicit separate pin.

Device-service tests inject discovery and connection adapters created on the same serial executor used for real USB work.  They cover stale connection identities, recovery failure blocking writes, retained originals after a partial clear, verified creation followed by a failed refresh, incomplete backups, and cancellation.  The system attachment adapter owns and releases registry references; simulated adapters never open USB devices.

The separate interface executable uses disposable sample snapshots and private preferences. It never opens a Neo or registers a login item. It checks native read-only text, fonts, and Return and Space handling for Clear and Replace, and captures the interface in Light and Dark appearances. This code is excluded from shipping app targets. Cached view images do not capture every system-composited toolbar or sidebar effect. Physical keyboard, accessibility, window-transition, and USB checks remain in the [manual checklist](tests/manual-checks.md).

```sh
scripts/verify-app.sh build/DerivedData/Build/Products/Release/universal/AlphaSync.app universal
scripts/verify-symbols.sh build/DerivedData/Build/Products/Release/universal
```

Repeat with `apple-silicon` for that edition. Verification checks exact architectures in both executables, macOS deployment commands, bundle versions, identifiers, selected icons, Help, native dependencies, signatures, and executable `--version` output on a matching host. Separate crash-symbol UUIDs must match each executable. `scripts/collect-builds.py` checks both editions, all twelve assets, checksums, signing state, and exact version, build, and source before collecting a download directory. It does not publish anything. These checks do not establish runtime or hardware compatibility on macOS 13.

Successful CI runs retain development app ZIPs, separate symbol ZIPs, SHA-256 checksums, build reports with the source commit, and interface screenshots on the [Actions page](https://github.com/koralatov/alphasync/actions). Artifacts expire. Public releases require an explicit manual workflow request. Both host jobs and a second check of the downloaded packages must pass before publication. Version 2.0 uses ad hoc signatures; it is not Apple-notarised. The separate `scripts/release.sh` route remains available for a Developer ID signed and notarised release when the required signing identity and notary profile are supplied.

Interrupted publication can resume an unpublished draft for the exact tested source and original package bytes. The publisher checks all existing asset hashes, uploads only missing files, and removes only expected empty `starter` assets left by failed GitHub uploads. Different hashes, unexpected assets, another source, and prereleases stop publication without replacing completed files. An already public release is recognised only when its source, tag, and every asset match; this check does not change it. Re-run the failed publication job with the original successful build artifacts; a fresh build whose bytes differ cannot overwrite that draft. Publication jobs are serialised across branches. Disposable command fixtures exercise this policy without contacting GitHub.

For 2.0.2, the authorised release run also enables `retire_superseded`. The separate retirement step checks the new public release, latest-release status, all asset hashes, and the frozen 1.5.1 release against the reviewed [retirement plan](releases/2.0.2-retirement.json). It validates every planned old listing before deleting any, records their metadata and notes in the retained publication artifact, then deletes only their release IDs. It never deletes Git tags. The final public listings must be exactly 1.5.1 and 2.0.2, with the protected releases rechecked afterwards. Partial retirement can resume safely.

The [2.0.2 release run](https://github.com/koralatov/alphasync/actions/runs/42802943901) passed on 10 November 2026 for source `807b4bedf1bb1cd655e934e1495723bb5c203c93`. Each host passed 109 Swift regressions, nine packaging fixtures, eighteen publication fixtures, eight retirement fixtures, and native interface checks. Both editions and helpers built on Apple Silicon; Universal and its helper also built on Intel. All twelve public asset sizes and hashes match the independently downloaded packages. The release is immutable and latest. Retirement left only 1.5.1 and 2.0.2 public, with all earlier tags and the legacy source and assets unchanged. Physical Neo, real Login Items approval, and macOS 13 runtime checks remain outstanding.

## USB and concurrency

Use Apple’s public **IOUSBHost** framework for bulk transfers. The Neo appears as USB vendor `081e`, product `bd04` in keyboard mode. Public HID output reports `e0` through `e4`, sent only to interface 1, switch it to the `bd01` file-transfer device. The proprietary file protocol uses bulk endpoints, not keyboard input reports.

There is no public `CommunicationUserHIDService` API in the SDK. A HID-only file engine would not match the Neo’s file-transfer interface. A DriverKit extension would require additional entitlements and installation; it is not required for this user-space client. API migration does not bypass Gatekeeper or system-controlled USB approval.

The transport uses the public SDK’s refined Swift entry points, which import some Objective-C selectors with a double underscore. This is Apple’s `NS_REFINED_FOR_SWIFT` naming, not a private framework call. Endpoint descriptors are inspected only at the transport boundary. Binary messages and file contents use bounded Swift buffers.

All USB handles, protocol transactions, and connection state belong to one serial executor. Async methods return immutable `Sendable` snapshots to the main actor. Reconnection creates a new UUID, so a queued request cannot be applied to a different connection. IOKit attachment notifications trigger discovery instead of a two-second polling loop. Each observer supplies an initial event, coalesces pending events, and releases its native port and iterators on cancellation. Events received during a transfer or confirmation are reconciled afterwards. Refresh and file reads remain explicit operations. The launch helper reads registry metadata only and leaves mode changes and transfers to the main app.

Monitor failures remain visible beside connected Neos until monitoring recovers. The app and helper share an observer watcher: failures retry after one and two seconds, then wait thirty seconds before a fresh burst. A minute of healthy monitoring resets that history. Wake notifications from `NSWorkspace.shared.notificationCenter` re-arm the observer; explicit retry also replaces it. Healthy monitoring has no periodic discovery timer. Failed app launches have their own bounded retry window, and only a successful launch or an already running app consumes an attachment.

Failed keyboard-mode handoffs remain visible until explicit retry or detachment.  Background scans do not repeatedly send a failed handoff sequence.  Cancelled requests are skipped before execution, and read-only transfers check cancellation between file blocks.  Once a writing operation starts, writing and read-back verification are allowed to finish.  Transfer deadlines use `ContinuousClock`, while backup dates and retention continue to use calendar time.

Each main-actor operation and reader owns a stop request. Quit stops read-only preparation, including the protocol engine’s final original-file check, and waits on checked continuations for active scopes to finish. Cancelling that waiter cannot bypass the wait. Once a multi-file change begins writing, all its writes and read-back verification finish before USB closes. Reader retries change the identity of the same SwiftUI task, so closing the window cancels a retry as well as its initial read.

File-operation failures retain the underlying error, completed and verified file count, possible unverified write, and recovery location as structured values.  Presentation does not inspect English error sentences to infer whether device contents changed.

## Imports, exports, and file protection

Exports and backups are **UTF-8 without a byte-order mark**, with LF line endings. Imports accept strict UTF-8, UTF-16 with a byte-order mark in either byte order, and MacASCII (Mac Roman). Unsupported Neo characters are rejected rather than silently replaced. This includes the unsupported `≡` character discussed during 1.5 development.

Dictionary imports report omitted words and require consent for the exact source text before continuing. Non-empty sources without valid words are rejected. Resumed batches retain earlier verified additions and never import those files twice.

Local imports must be regular files and are bounded to 4 MiB plus one detection byte. A non-blocking open prevents named pipes from holding up device work. File-name conversion is strict, with a 15-byte device limit. No silent truncation is used.

Converted device bytes are validated against fresh applet limits and available memory before a writing command. Replacements can reuse their current allocation; growth keeps 1,024 bytes in reserve. Missing or invalid limits stop the import. Changed contents are read back and compared. Errors after writing begins say that the device may already have changed.

AlphaWord and user dictionary files support imports and changes. Other applet formats are read-only in 2.0: their exports and backups preserve raw bytes in UTF-8 XML. Opaque-format imports are deliberately unavailable until they can be validated safely.

Replace and Clear prepare a warning without writing, retain the original bytes, and recheck those originals before proceeding. Cancel is the default and initial focus. Requested recovery copies save both readable text and raw `.neo` bytes in private folders before any destructive operation. Failure to complete the copy stops the change. A later failure includes the recovery location. This is recovery material, not an atomic USB rollback or Edit → Undo.

Local files are synchronised to private temporary files and published with an exclusive rename. Existing exports are preserved. Backups and recovery folders retain an incomplete suffix until successfully completed. Optional **AlphaSync Backup Log.plist** files stay inside the dated backup folder, use relative paths, and are off by default. Recovery metadata uses format version 2; backup logs use version 3. Retention moves only recognised version 1 or 2 recovery folders to Trash and skips incomplete folders and directory symlinks.

Backup destinations use Foundation bookmarks, resolved without mounting a drive or opening system UI. Existing paths migrate when used. First use creates the default destination and records its bookmark before any backup or recovery write. Opening the app or Settings does not create that folder. A missing or invalid saved destination blocks the operation without recreating its old path. Recovery preparation and retention checks can stop before a destructive write; incomplete copies remain identifiable.

File sizes use Finder-style decimal bytes and KB. Exact byte counts use regional grouping, for example `51,200 bytes`. Native system fonts, appearance, and accessible controls remain in use.

## Automatic opening and Help

Settings uses `SMAppService` on every supported 2.0 system. The saved automatic-opening preference and the actual login-item status are shown separately. Keep the helper inside the containing app, move the app to Applications before enabling it, and follow the system’s approval prompts. If an old installation starts a separate helper from Application Support, disable it before replacing the app.

SwiftUI supplies the standard Help menu. AlphaSync Help is first, with ⌘?, followed by version-specific notes, the offline licence, and GitHub, issue, and contact commands. The build phase generates the licence from the original `LICENSE` and indexes Help with `hiutil`. Development builds link to notes for their version on master; stable builds link to their exact release tag.

Issue and contact commands open editable forms containing only version, build, edition, macOS version, and process architecture. They include no file contents, paths, device identifiers, or attachments. Sending remains with the user.
