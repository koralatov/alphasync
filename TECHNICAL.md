# Technical guide

Version 1.6 is being developed on **master**. Both app targets require **macOS 13 or later**. For installation and everyday use, see the [README](README.md).

## Shared source and editions

| Target and scheme | Architectures | Minimum macOS | Icon |
| --- | --- | --- | --- |
| AlphaSyncUniversal | x86_64 and arm64 | 13.0 | Original |
| AlphaSyncAppleSilicon | arm64 | 13.0 | Modern |

Each target embeds its matching Swift `AlphaSyncLauncher.app` in `Contents/Library/LoginItems`. Apps and helpers use the existing bundle identifiers, `com.tsoniq.AlphaSync` and `com.tsoniq.AlphaSyncLauncher`, and share version and build settings. Install one app edition at a time.

The application, business logic, protocol engine, and codecs are Swift. The file manager uses SwiftUI’s sidebar, table, toolbar, forms, sheets, and window scenes. A small public AppKit adapter provides genuinely non-editable selectable text and the native Find bar on macOS 13. Pasteboard, Help Viewer, workspace actions, and orderly termination also use public native integrations. There are no third-party runtime dependencies.

The shared Swift package contains:

- `AlphaSyncCore`: bounded binary parsing, typed snapshots, protocol transactions, codecs, limits, and atomic local files.
- `AlphaSyncHardware`: serial USB ownership, discovery, async operations, backups, and recovery copies.
- `AlphaSyncUI`: shared SwiftUI views, preferences, and commands.

`Sources/AlphaSyncApp` and `Sources/AlphaSyncLauncher` provide the executable entry points. Only the dedicated arm64 target compiles `Sources/AlphaSyncSilicon/EditionGuard.swift`. This rejects an Intel or incorrectly configured Silicon build and provides a place for future genuine architecture-specific integrations. No exclusive hardware feature has been invented for the current edition. Swift concurrency is shared by both architectures.

The [migration plan](docs/1.6-migration.md) records decisions, milestones, and outstanding validation.

## Build

Use **Xcode 26.6**, pinned in [.xcode-version](.xcode-version), for canonical development packages. CI also checks the Universal target on an Intel host with Xcode 16.4. Both use Swift 6 with strict concurrency checking. The build host can run a newer macOS than the app’s minimum.

```sh
xcodebuild -project AlphaSync/AlphaSync.xcodeproj \
  -scheme AlphaSyncUniversal -configuration Release \
  -destination 'generic/platform=macOS' \
  -derivedDataPath build/DerivedData build

xcodebuild -project AlphaSync/AlphaSync.xcodeproj \
  -scheme AlphaSyncAppleSilicon -configuration Release \
  -destination 'generic/platform=macOS' \
  -derivedDataPath build/DerivedData build
```

Apps and separate dSYMs appear under `build/DerivedData/Build/Products/Release/universal` and `Release/apple-silicon`. Keep each app bundle intact. [Version.xcconfig](AlphaSync/Build/Version.xcconfig) supplies version **1.6**, build **148**, and the **development** release channel to both apps and helpers.

The checked-in Xcode project is generated by `python3 scripts/generate-project.py`. Run it after changing target definitions in that script. Generation uses Python’s standard library and preserves stable object identifiers. Python is not required to run the app.

## Milestone checks

Routine commits use `[skip ci]`. Compile and test at the documented major milestones, completion, or a focused correction to a failed milestone.

```sh
swift build --product AlphaSyncUIChecks
swift test --parallel
swift run --skip-build AlphaSyncUIChecks build/interface-checks
```

Core regressions cover wire frames, truncated replies, character conversion, UTF-16 byte orders, dictionary bounds, unsupported text, file limits, low memory, exclusive exports, and incomplete folders. Simulated transfer checks include multi-block writes, read-back mismatches, changed originals, and a 2 MB import rejected before file-writing commands.

The separate interface executable uses disposable sample snapshots and private preferences. It never opens a Neo or registers a login item. It checks native read-only text, fonts, and Return and Space handling for Clear and Replace, and captures the interface in Light and Dark appearances. This code is excluded from shipping app targets. Cached view images do not capture every system-composited toolbar or sidebar effect. Physical keyboard, accessibility, window-transition, and USB checks remain in the [manual checklist](tests/manual-checks.md).

```sh
scripts/verify-app.sh build/DerivedData/Build/Products/Release/universal/AlphaSync.app universal
scripts/verify-symbols.sh build/DerivedData/Build/Products/Release/universal
```

Repeat with `apple-silicon` for that edition. Verification checks exact architectures in both executables, macOS deployment commands, bundle versions, identifiers, selected icons, Help, native dependencies, signatures, and executable `--version` output on a matching host. Separate crash-symbol UUIDs must match each executable. `scripts/collect-builds.py` checks both editions, all twelve assets, checksums, signing state, and exact version, build, and source before collecting a download directory. It does not publish anything. These checks do not establish runtime or hardware compatibility on macOS 13.

Successful CI runs retain development app ZIPs, separate symbol ZIPs, SHA-256 checksums, build reports with the source commit, and interface screenshots on the [Actions page](https://github.com/koralatov/alphasync/actions). Artifacts expire. There is no automatic 1.6 release publication.

## USB and concurrency

Use Apple’s public **IOUSBHost** framework for bulk transfers. The Neo appears as USB vendor `081e`, product `bd04` in keyboard mode. Public HID output reports `e0` through `e4`, sent only to interface 1, switch it to the `bd01` file-transfer device. The proprietary file protocol uses bulk endpoints, not keyboard input reports.

There is no public `CommunicationUserHIDService` API in the SDK. A HID-only file engine would not match the Neo’s file-transfer interface. A DriverKit extension would require additional entitlements and installation; it is not required for this user-space client. API migration does not bypass Gatekeeper or system-controlled USB approval.

The transport uses the public SDK’s refined Swift entry points, which import some Objective-C selectors with a double underscore. This is Apple’s `NS_REFINED_FOR_SWIFT` naming, not a private framework call. Endpoint descriptors are inspected only at the transport boundary. Binary messages and file contents use bounded Swift buffers.

All USB handles, protocol transactions, and connection state belong to one serial executor. Async methods return immutable `Sendable` snapshots to the main actor. Reconnection creates a new UUID, so a queued request cannot be applied to a different connection. Only metadata is polled for unchanged devices; refresh and file reads are explicit operations. The launch helper reads registry metadata only and leaves mode changes and transfers to the main app.

## Imports, exports, and file protection

Exports and backups are **UTF-8 without a byte-order mark**, with LF line endings. Imports accept strict UTF-8, UTF-16 with a byte-order mark in either byte order, and MacASCII (Mac Roman). Unsupported Neo characters are rejected rather than silently replaced. This includes the unsupported `≡` character discussed during 1.5 development.

Local imports must be regular files and are bounded to 4 MiB plus one detection byte. A non-blocking open prevents named pipes from holding up device work. File-name conversion is strict, with a 15-byte device limit. No silent truncation is used.

Converted device bytes are validated against fresh applet limits and available memory before a writing command. Replacements can reuse their current allocation; growth keeps 1,024 bytes in reserve. Missing or invalid limits stop the import. Changed contents are read back and compared. Errors after writing begins say that the device may already have changed.

AlphaWord and user dictionary files support imports and changes. Other applet formats are read-only in 1.6: their exports and backups preserve raw bytes in UTF-8 XML. Opaque-format imports are deliberately unavailable until they can be validated safely.

Replace and Clear prepare a warning without writing, retain the original bytes, and recheck those originals before proceeding. Cancel is the default and initial focus. Requested recovery copies save both readable text and raw `.neo` bytes in private folders before any destructive operation. Failure to complete the copy stops the change. A later failure includes the recovery location. This is recovery material, not an atomic USB rollback or Edit → Undo.

Local files are synchronised to private temporary files and published with an exclusive rename. Existing exports are preserved. Backups and recovery folders retain an incomplete suffix until successfully completed. Optional **AlphaSync Backup Log.plist** files stay inside the dated backup folder, use relative paths, and are off by default. Recovery metadata uses format version 2; backup logs use version 3. Retention moves only recognised version 1 or 2 recovery folders to Trash and skips incomplete folders and directory symlinks.

File sizes use Finder-style decimal bytes and KB. Exact byte counts use regional grouping, for example `51,200 bytes`. Native system fonts, appearance, and accessible controls remain in use.

## Automatic opening and Help

Settings uses `SMAppService` on every supported 1.6 system. The saved automatic-opening preference and the actual login-item status are shown separately. Keep the helper inside the containing app, move the app to Applications before enabling it, and follow the system’s approval prompts. If an old installation starts a separate helper from Application Support, disable it before replacing the app.

SwiftUI supplies the standard Help menu. AlphaSync Help is first, with ⌘?, followed by version-specific notes, the offline licence, and GitHub, issue, and contact commands. The build phase generates the licence from the original `LICENSE` and indexes Help with `hiutil`. Development builds link to the 1.6 development notes; a future stable channel links to its exact release tag.

Issue and contact commands open editable forms containing only version, build, edition, macOS version, and process architecture. They include no file contents, paths, device identifiers, or attachments. Sending remains with the user.
