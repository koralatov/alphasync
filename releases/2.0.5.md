# AlphaSync 2.0.5 – not released

AlphaSync copies and backs up text from an AlphaSmart Neo on a Mac. This test build requires macOS 13 or later and is prepared as version 2.0.5, build 159.

## Connection correction

A hardware report shows that 2.0.4 can leave a Neo in keyboard mode on an M2 MacBook Air, while 1.5.1 connects correctly on the same Mac.

This candidate restores the USB configuration and mode-switch command sequence used by 1.5.1, through the current public USB framework. It also detects the Neo directly as a USB device and shows a connection failure if the switch fails.

On 15 November 2026, the user reported that the connection now works on the M2 Air. The screenshot confirms a connected file list, with a separate layout problem addressed in build 159. Real transfers, backup, and file changes still need their functional checks. No public 2.0.5 download is available yet.

## Technical information

The [connection investigation](../docs/neo-keyboard-mode.md) records the hardware report, exact legacy control requests, scope, regression checks, and required physical tests. Both editions share this correction. File transfers, recovery copies, and the validated offline Help are retained.

Builds for both Intel and Apple Silicon, the full test suite, Help and package validation, and native interface checks are required before considering publication. Public releases, source tags, and existing downloads are not replaced by this candidate.

## Crash correction in build 156

The first test build quit unexpectedly during USB access on macOS 14.7.1. The crash report located incorrect handling of a fixed-size macOS USB buffer. Build 156 uses ordinary, owned buffers for connecting, reading, and writing, with explicit checks of buffer sizes and completed byte counts. The new buffer tests and full build checks must pass, followed by physical Neo verification.

## File-list correction in build 157

The latest hardware report shows that the Neo recognises the manager connection, but AlphaSync fails while opening it with reply 0x90. The rewrite asked the Neo’s System applet for a file count, although that applet does not supply one. Build 157 removes that request and handles confirmed fileless read-only applets without discarding real file errors. Further errors include the rejected request and applet ID for diagnosis. Eight new wire tests cover the full connection and file-read path. The [investigation](../docs/neo-parameter-reply.md) defines the full non-publishing build milestone and remaining physical test.

## USB review in build 158

The full comparison with 1.5.1 found two further differences. Build 158 gives the Neo the same ten connection probes as the working older version. It also stops at an incomplete USB reply, so bytes from a later reply cannot be mistaken for its missing contents. USB cleanup now aborts both transfer pipes before releasing an unclosed interface.

The [technical audit](../docs/usb-parity-audit.md) records exact mode-switch commands, packet sizes, fields, checksums, timeouts, and file operations. Twenty-four new regressions extend the Swift suite to 155. Physical Neo checks remain open.
