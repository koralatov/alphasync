# AlphaSync 2.0.1

Archived development notes for build 150. This version was never published. Its changes are included in [2.0.3](2.0.3.md), the current modern release.

AlphaSync is a free Mac app for reading, copying, and backing up files from an AlphaSmart Neo. Both editions require macOS 13 or later. The Universal edition supports Intel and Apple Silicon; the Apple Silicon edition supports M-series Macs. Both have the same features.

## What changes in this version

- **More reliable automatic opening.** Enabling the option saves your choice before macOS starts the helper. A failed opening gets up to three attempts instead of being forgotten until you reconnect the Neo.
- **Quicker backup stopping.** Stop and Quit can interrupt a backup between blocks of the file being read. Files already saved stay on your Mac, and unfinished folders keep their incomplete marker.
- **Clearer connection messages.** A problem with one Neo stays visible while another Neo is connected. Try Again remains available beside the file list.
- **Dictionary import review.** AlphaSync explains when words are too short or too long for the Neo’s dictionary. You can cancel or continue with the usable words. A non-empty file with no usable words is rejected.
- **Backup folders that follow moves.** Saved folder references follow renames and moves. If the destination is unavailable, AlphaSync asks you to reconnect its drive or choose it again instead of recreating the old path.
- **USB notifications.** The app and helper respond to attachment events instead of checking every two seconds. Connections made during a transfer or confirmation are handled afterwards.

## Downloading, installing, and using AlphaSync

There are no public 2.0.1 downloads. Use the [2.0.3 release page](https://github.com/koralatov/alphasync/releases/tag/v2.0.3) for downloads, installation instructions, and everyday use. The earlier development builds identified themselves as 2.0.1, build 150. Install one edition at a time.

## Technical information

### Fixes since 2.0

`SMAppService` owns the helper’s lifetime. The helper no longer depends on a possibly delayed cross-process preference read. Registration failures restore the saved intent, approval-required states retain it, and Settings refreshes the actual status when the app becomes active.

Automatic launches use a separately tested state machine. A successful launch or an already running app consumes an attachment. Failures use one- and two-second retry delays, with a maximum of three attempts. Detachment removes pending work, and reconnection allows a fresh attempt.

Backup reads pass cancellation through to the protocol engine’s block checks. Cancellation retains completed files and records a stopped result without reporting a device failure. Active writing and read-back verification still finish safely before shutdown.

Connection warnings and status use separate rows around the native split view. The browser is clipped to its allocated space. Native interface checks verify that a warning changes the rendered window, moves the file table down, and leaves room for the status row.

Dictionary conversion returns accepted and omitted counts with bounded examples. Consent applies to the exact source text. Editing the source requires a fresh review, and resuming a batch preserves earlier verified additions without repeating them. Deliberate Clear operations can still use empty dictionary data.

Saved backup destinations use Foundation bookmarks, resolved without mounting drives or showing system UI. Existing valid paths migrate when used. Resolution failure stops backups and requested recovery copies. It does not fall back to recreating the saved path.

IOKit matching and termination notifications run on a private serial queue. Observers drain their initial iterators, coalesce pending events, and explicitly release ports and iterators when their event loop ends. Main-actor discovery waits until transfers and confirmations finish. Monitor failures remain visible until explicit retry; the helper has bounded monitor-setup retries.

### Release tooling

Interrupted publication can resume an unpublished stable draft for the exact tested source and original verified packages. Existing asset hashes must match. The publisher uploads missing files and removes only expected empty GitHub `starter` assets left by failed uploads. Different bytes, unknown assets, conflicting tags, another source, and public or immutable releases stop the process. Publication jobs are serialised, and every asset is checked before publication.
