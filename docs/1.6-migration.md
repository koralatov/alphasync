# AlphaSync 1.6 migration

Work takes place on master. Version 1.5.1, its protected legacy branch and tag, and its immutable downloads remain untouched.

## Scope

Both new app targets support macOS 13 and later. Universal builds x86_64 and arm64. Apple Silicon builds arm64 only. They share Swift application, protocol, and SwiftUI view sources; target settings select the architecture, edition description, and icon. No architecture-exclusive feature is added merely to make the editions look different.

The existing device engine is C++, and the application layer is Objective-C++. Its established wire protocol and character tables are the migration reference. Replace binary parsing with bounded Swift values and Data, preserve the BSD notices, and keep original behaviour covered by parity tests.

## Milestones

1. **Swift core.** Add the shared package, typed device models, bounded protocol messages, text codecs, and size validation. At this milestone, run the portable core regressions and compare established fixtures.
2. **USB service.** Move device access to Swift and public IOUSBHost bulk pipes. Use a serial I/O executor behind async methods, connection generations, complete enumeration, bounded transfers, and read-back verification. Check the compiled transport at this milestone. Hardware behaviour remains explicitly unverified until tested with a Neo.
3. **Swift application and SwiftUI.** Replace the application layer, settings, file list, read-only windows, Inspector, About, and native Help commands. Keep safe Cancel defaults, system fonts, appearance, copying, imports, backups, and recovery-before-write safeguards. Use small AppKit adapters only where SwiftUI lacks a public macOS 13 equivalent, such as pasteboard and workspace operations; no custom-drawn controls.
4. **Two native app targets.** Build both editions from the shared source, with matching Swift login helpers and macOS 13 deployment targets. Enforce arm64 at compile time in the Silicon edition. Run the full build and regression checks here.
5. **Review and documentation.** Update user and developer guidance, record remaining hardware checks, and retain development artifacts. Do not publish a 1.6 release without a separate release request.

Each focused commit explains one change. Routine commits use [skip ci]. Compile and test only at these major milestones or at completion, unless a failure needs a focused correction.

## Hardware decision

The Neo enumerates as vendor 0x081e, product 0xbd04 in keyboard/HID mode. The existing mode-switch sequence sends output reports 0xe0 through 0xe4 to interface 1. It reconnects as product 0xbd01 and transfers proprietary eight-byte protocol frames over bulk endpoints. A HID-only file-transfer implementation would not match that hardware interface.

Use the public IOUSBHost framework for bulk communication and public HID APIs only for the keyboard-mode handoff. Never capture or seize another driver’s device, bypass macOS security, or request input monitoring to read keystrokes. Surface access errors clearly. A custom DriverKit extension would require Apple-granted entitlements and system-extension installation; it is not required for this app-level USB client. Changing USB APIs does not remove Gatekeeper or system-controlled accessory approval.

References: [IOUSBHostInterface](https://developer.apple.com/documentation/iousbhost/iousbhostinterface), [IOUSBHostPipe](https://developer.apple.com/documentation/iousbhost/iousbhostpipe), and [DriverKit entitlements](https://developer.apple.com/documentation/driverkit/requesting-entitlements-for-driverkit-development).

## Data protection requirements

- Do not send a writing command before conversion, file limits, available memory, and any requested recovery copy succeed.
- Stop on an incomplete applet or file enumeration. An unknown count is not zero.
- Keep every USB transaction on one serial executor. Reconnection creates a new connection identity; queued work must not reach a different Neo.
- Read back changed bytes before reporting success. After a write has begun, explain that data may have changed if verification fails.
- Export UTF-8 with exclusive, atomic file publication. Preserve existing files, mark incomplete backups, and keep optional logs inside each dated folder.
- Keep recovery enabled by default. Never silently replace unsupported characters, overwrite a backup, or permanently delete retained copies.
